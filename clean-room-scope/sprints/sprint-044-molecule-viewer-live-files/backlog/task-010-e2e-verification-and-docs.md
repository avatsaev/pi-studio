- **Sprint:** sprint-044-molecule-viewer-live-files
- **Status:** backlog
- **Estimated size:** S

## Goal
Prove the whole sprint works against a real daemon in a browser, then bring every affected doc in line
with the code that now exists.

## Background / why
Tasks 001-009 each verify their own slice, but three behaviors only exist once everything is wired:
molecule tab from the explorer, empty molecule tab from the "+" menu, and live updates (viewer reload
+ file tree) driven by real filesystem events.

**Daemon choice matters here.** The molecule viewer fetches through the chunked binary download path,
and `file_download_token_request`/`file_download_request` are registered **only** in the production
bootstrap (`bootstrap.ts:429-434`); `dev-bootstrap.ts` registers a bare `FileExplorerService` with no
download-token issuer (line 252) and no git-checkout/file-watch handlers. So this must be verified
against the **production daemon** (`npm start`), not `npm run dev:daemon`.

### 2. Browser smoke test (the actual proof)
Production daemon plus the web-client dev server. Prepare a scratch workspace containing at least a
`.pdb` (or `.cif`/`.xyz`) file.
- **Behavior 1** — click the molecular file in the tree → a molecule tab opens and renders the
  structure. Rotate/zoom it. Click a `.md` file → still opens the normal text viewer.
- **Behavior 2** — "+" → "New molecule view" → an empty molecule tab with molviewer's own drag-drop
  empty state; drop a molecular file onto it and confirm it loads.
- **Hidden-tab resize** — switch to another tab and back; the viewer must be correctly sized and still
  show the same camera/selection (this is task-003's `[VERIFY]` item; record the observed behavior).
- **Behavior 3a, live reload** — from a shell, append an atom line to the open file → the viewer reloads
  within ~1 s with the camera preserved.
- **Behavior 3b, the edit gate** — make an edit inside the viewer, then modify the file on disk again →
  **no** reload, edits intact, stale indicator shown. Undo back to clean, modify again → reload resumes.
- **Behavior 3c, live tree** — from a shell in an expanded directory: `touch a.txt` (row appears),
  `mv a.txt b.txt` (row renames), `rm b.txt` (row disappears), then `git checkout` a branch that
  adds/removes files (rows update). All without manual refresh.
- **Cleanup** — close the molecule tab and collapse directories; confirm from the daemon log that
  watchers are released. Kill the browser tab outright (not a graceful close) and confirm the
  session-close sweep releases the remaining watchers (task-005).
- **Bundle** — confirm `vendor-molviewer-*.js` exists in the production build, is multi-MB, and is
  fetched only when a molecule tab first opens (Network panel), not on initial page load.
- **Large files (task-009)** — with fixtures generated by `head -c`, open in turn: a 2 MB file
  (renders inline; would have failed before this sprint), a 12 MB file (renders via the streaming
  fallback, with the muted "streamed" note), and a 48 MB file (size-aware terminal state, working
  download, no render attempt). Also confirm the daemon stays responsive during the 12 MB read —
  the agent stream/terminal must not visibly stall (the async-read change in task-009).
