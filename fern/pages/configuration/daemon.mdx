The daemon reads `$PI_STUDIO_HOME/config.json` and the environment variables below — set them
before `pi-studio daemon start`, or pass them to `docker compose` (see [Docker](/configuration/docker)).
All are optional.

| Variable | Default | Purpose |
|---|---|---|
| `PI_STUDIO_HOME` | `~/.pi-studio` | State + config + logs directory |
| `PI_STUDIO_LISTEN` | `0.0.0.0:6767` | Daemon listen address (`host:port`) |
| `PI_STUDIO_PASSWORD` | _(unset)_ | Require this password for connections (bcrypt-checked) |
| `PI_STUDIO_HOSTNAMES` | `localhost,*.localhost` | Allowed `Host` header values (literal IPs always allowed) |
| `PI_STUDIO_SERVER_ID` | _(generated UUID)_ | Stable server identity |
| `PI_STUDIO_LOG_LEVEL` | `info` | pino log level |
| `PI_STUDIO_RELAY_ENABLED` | `false` | Opt in to dialing out to a relay — see [E2EE relay](/configuration/relay) |
| `PI_STUDIO_RELAY_ENDPOINT` | _(unset)_ | Relay `host:port` to dial |
| `PI_STUDIO_RELAY_USE_TLS` | `false` | Use `wss://` to reach the relay |

Example — run on a different port with a password and an isolated home:

```bash
PI_STUDIO_HOME=/tmp/pi-studio-dev \
PI_STUDIO_LISTEN=127.0.0.1:6790 \
PI_STUDIO_PASSWORD=hunter2 \
pi-studio daemon start
```

## Passwords and pairing keys

A password can also be set on an already-running daemon:

```bash
pi-studio daemon set-password hunter2
```

This bcrypt-hashes the password into `config.json` and enforces it on the daemon's next start.

To revoke every pairing link/QR ever issued (for example, one that leaked), mint a fresh keypair:

```bash
pi-studio daemon rotate-key
```

The daemon mints a new keypair, restarts, and prints a fresh QR — all clients must re-pair, but
your password and relay settings are untouched.

## The `pi` provider

The `pi` CLI is bundled inside `@earendil-works/pi-coding-agent` — the daemon launches
`node <pkg>/dist/cli.js --mode rpc`, so no global `pi` install is required. You only need pi
*authenticated*; see [CLI reference: Daemon & Auth](/cli-reference/daemon-and-auth#auth) for
`pi-studio auth login`, or set `ANTHROPIC_API_KEY` (etc.) directly in the daemon's environment.

To use a different `pi` than the bundled one, point the daemon at an absolute path in
`$PI_STUDIO_HOME/config.json`:

```json
{ "agents": { "providers": { "pi": { "command": ["/abs/path/to/pi", "--mode", "rpc"] } } } }
```

A missing or unresolvable `pi` surfaces as a clean `rpc_error` ("Pi provider unavailable…")
instead of crashing the daemon. A literal `~` in a `cwd` field is expanded to your home
directory. For a dependency-free smoke test, use the `mock` provider instead of `pi`.
