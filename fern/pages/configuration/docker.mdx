Three images, all built from local monorepo source:

| Image | Package | Base | Contents |
|---|---|---|---|
| `pi-studio-daemon` | `@av-pi-studio/server` | `node:22-bookworm-slim` | daemon + compiled `node-pty` + `git` + bundled `pi` runtime |
| `pi-studio-relay` | `@av-pi-studio/relay` | `node:22-bookworm-slim` | standalone [E2EE relay](/configuration/relay) (pure JS, no native, stateless) |
| `pi-studio-web-client` | `@av-pi-studio/web-client` | `nginx:1.27-alpine` | static React/Vite SPA (relay-only "Lite" client: it connects with a pairing link) |

The daemon and relay bind `0.0.0.0`, are driven by environment variables, and shut down cleanly
on `SIGTERM`; the web UI is a static bundle served by nginx.

## Quick start with compose

```bash
cd docker
PI_STUDIO_PASSWORD=choose-a-password docker compose up --build   # the password is required
```

This starts the relay (`:7000`), the daemon (`:6767`), and the web UI (`:8080`), with the daemon
dialing **outbound** to the relay so the full `client → relay → daemon` topology runs locally. The
daemon listens on `0.0.0.0` inside the container, so it **refuses to start without
`PI_STUDIO_PASSWORD`** (compose fails with "set PI_STUDIO_PASSWORD" if it is unset). Then:

```bash
# drive it from the CLI, direct to the daemon port, with the password
pi-studio --host http://localhost:6767 --password "$PI_STUDIO_PASSWORD" ls
# health probes
curl http://localhost:6767/api/health   # → {"status":"ok","version":"<daemon version>"}
curl http://localhost:7000/health        # → ok
curl http://localhost:8080/ -I           # → 200 (SPA)
```

<Note>
  **The web UI connects through the relay only, with a pairing link.** It never dials the daemon
  port, and the daemon refuses any browser WebSocket (an upgrade that carries an `Origin`). The
  daemon image does not ship the CLI, so generate the link on the host from a copy of the daemon's
  public key (delete the copy afterwards — the file also holds the private key):

  ```bash
  mkdir -p /tmp/pi-home && docker compose cp daemon:/data/daemon-keypair.json /tmp/pi-home/
  PI_STUDIO_HOME=/tmp/pi-home PI_STUDIO_APP_BASE_URL=http://localhost:8080 \
    PI_STUDIO_RELAY_ENABLED=true PI_STUDIO_RELAY_PUBLIC_ENDPOINT=localhost:7000 \
    PI_STUDIO_RELAY_PUBLIC_USE_TLS=false pi-studio daemon pair
  rm -r /tmp/pi-home
  ```

  Open the printed link in the browser. The desktop app and the CLI connect to the daemon port
  directly, with the password.
</Note>

Compose knobs (all optional):

| Variable | Default | Effect |
|---|---|---|
| `PI_STUDIO_DAEMON_PORT` | `6767` | Host port mapped to the daemon |
| `PI_STUDIO_RELAY_PORT` | `7000` | Host port mapped to the relay |
| `PI_STUDIO_WEB_PORT` | `8080` | Host port mapped to the web UI |
| `PI_STUDIO_PASSWORD` | **required** | Connection password (bcrypt-checked); the daemon refuses a network bind without it |
| `PI_STUDIO_INSTALL_GH` | `false` | Bundle the GitHub CLI (`gh`) into the daemon image |
| `ANTHROPIC_API_KEY` | _(unset)_ | `pi` provider credential — see [Provider auth](#provider-auth) |

## Building the images individually

The build context **must** be the repo root, since workspace dependencies resolve there:

```bash
docker build -f docker/relay.Dockerfile      -t pi-studio-relay      .
docker build -f docker/daemon.Dockerfile     -t pi-studio-daemon     .
docker build -f docker/web-client.Dockerfile -t pi-studio-web-client .

# daemon with the GitHub CLI included:
docker build -f docker/daemon.Dockerfile --build-arg INSTALL_GH=true -t pi-studio-daemon .
```

`web-client.Dockerfile` also accepts `PI_STUDIO_BRAND_TITLE`/`PI_STUDIO_BRAND_ICON` build args for
a white-label build — see [Branding the UI](/web-ui#branding-the-ui).

## Running individually

### Daemon

```bash
docker run -d --name pi-studio-daemon \
  -p 6767:6767 \
  -e PI_STUDIO_PASSWORD=hunter2 \
  -e ANTHROPIC_API_KEY=sk-ant-... \
  -v pi-studio-data:/data \
  -v /abs/path/to/projects:/workspace \
  pi-studio-daemon
```

| Variable | Default | Purpose |
|---|---|---|
| `PI_STUDIO_LISTEN` | `0.0.0.0:6767` | Bind address; a non-loopback bind requires `PI_STUDIO_PASSWORD` |
| `PI_STUDIO_HOME` | `/data` | State dir (mount a volume here) |
| `PI_STUDIO_PASSWORD` | **required** | Connection password |
| `PI_STUDIO_LOG_LEVEL` | `info` | pino level; `debug` adds per-RPC request lines |
| `PI_STUDIO_RELAY_ENABLED` / `_ENDPOINT` / `_USE_TLS` | `false` / — / `false` | Dial out to a relay |
| `PI_STUDIO_APP_BASE_URL` | `https://app.molagent.ai` | Pairing link origin (`daemon pair`) — the compose stack sets this to `http://localhost:${PI_STUDIO_WEB_PORT:-8080}` |

The daemon logs its full lifecycle to stdout as NDJSON, so `docker logs -f pi-studio-daemon`
works out of the box; a rotating copy also lands in `/data/logs/` on the data volume. See
[Daemon configuration](/configuration/daemon) for the full set of daemon environment variables.

### Relay

```bash
docker run -d --name pi-studio-relay -p 7000:7000 pi-studio-relay
```

Stateless, no volumes. Environment: `PI_STUDIO_RELAY_LISTEN` (default `0.0.0.0:7000`),
`PI_STUDIO_RELAY_LOG_LEVEL` (default `info`; `trace` adds per-frame byte counts), and
`PI_STUDIO_RELAY_LOG_DIR` (also write rotating NDJSON files there).

### Web UI

```bash
docker run -d --name pi-studio-web-client -p 8080:8080 pi-studio-web-client
```

Static SPA on `:8080`, no volumes, no daemon address: the page is opened from a pairing link
(`pi-studio daemon pair`) and reaches the daemon through the relay. nginx proxies nothing.

## Volumes

- **`/data`** (`PI_STUDIO_HOME`) — persistent daemon state: agent records, the pairing keypair,
  server identity, logs, and project registries. Use a named volume so agents, projects, and the
  relay identity survive restarts.
- **`/workspace`** — bind-mount the host directories your agents operate on. Agents spawn their
  provider process (and terminals, git, worktrees) in these `cwd`s, so the paths you open via the
  client (for example `pi-studio open /workspace/my-repo`) must exist inside the container.

## Provider auth

The `pi` CLI is bundled in the image, but it still needs credentials. Either:

- set **`ANTHROPIC_API_KEY`** (or another provider key) in the daemon's environment, or
- mount your host credentials read-only — uncomment the `auth.json` line in `docker-compose.yml`:
  `- "${HOME}/.pi/agent/auth.json:/home/node/.pi/agent/auth.json:ro"`.

Without credentials the `pi` provider surfaces a clean `rpc_error`; the built-in **`mock`**
provider works with no credentials for smoke tests.

## Updating

A daemon in a container never updates itself (`PI_STUDIO_INSTALL_KIND=docker`): a connected client shows
that it cannot update and the command to run, `docker compose pull && docker compose up -d`. Replace the
image, keep the `/data` volume.

## Security notes

- The relay is zero-knowledge — it forwards ciphertext verbatim and never sees message contents.
  The **daemon** port, however, is a plain WebSocket endpoint: it requires `PI_STUDIO_PASSWORD` on a
  network bind, refuses browser upgrades, and should still be kept off untrusted networks. TLS
  (`wss`/`https`) is expected to be terminated by a reverse
  proxy in front of the daemon; the container itself speaks plaintext HTTP.
- The daemon and relay images run as the non-root `node` user.
- `GET /api/health` (daemon) and `GET /health` (relay) are exempt from auth/host checks for
  probes.
