`pi-studio ui` serves the production Pi-Studio browser UI — a three-column workspace (sessions
on the left, chat/terminal/code in the middle, files and git changes on the right) — as a static
site, with no separate install or build step. Point it at any daemon, local or remote:

```bash
pi-studio ui                                    # serves on http://localhost:4173, connects to the local daemon
pi-studio ui --ui-port 8080 --daemon-host workstation.local:6767
```

| Flag | Description |
|---|---|
| `--ui-host <host>` | Interface the static server binds to |
| `--ui-port <port>` | Port the static server listens on (default `4173`) |
| `--daemon-host <host>` | Pre-fills the printed URL's `?host=&connect=1` so the browser tab auto-connects (falls back to the global `--host`) |

The command serves the built `@av-pi-studio/web-client` SPA (`dist/web`) via a minimal static
file server with SPA fallback — it never itself probes or starts a daemon — and blocks until
`SIGINT`/`SIGTERM`.

## Pointing the agent at a file

Drag a file or folder from the Files tree onto the chat composer to insert its workspace-relative
path into your prompt at the cursor (folders end in `/`, and names with spaces are wrapped in
backticks).

## Branding the UI

The toolbar title and the browser favicon can be overridden **at build time**, with no source
changes — useful for a reseller/operator shipping their own branded distribution. With both
variables unset, the build is byte-for-byte the default Pi-Studio distribution; no theme, accent
color, or logo override is part of this mechanism.

| Variable | Default | Effect |
|---|---|---|
| `PI_STUDIO_BRAND_TITLE` | `Pi-Studio` | The document `<title>` and the connection bar's brand label |
| `PI_STUDIO_BRAND_ICON` | _(unset → default favicon)_ | Path to a `.svg`, `.png`, or `.ico` file that replaces the favicon |

```bash
PI_STUDIO_BRAND_TITLE="Acme Coder" \
PI_STUDIO_BRAND_ICON="/path/to/acme-icon.svg" \
npm run build:web -w @av-pi-studio/web-client
```

Each variable is independent — set only the title, only the icon, or neither. Both are also
honored by the dev server, so a branded checkout previews correctly locally. `PI_STUDIO_BRAND_ICON`
must point at an existing `.svg`, `.png`, or `.ico` file: a missing file or an unsupported
extension fails the build with a clear error rather than silently falling back to the default
icon. `docker/web-client.Dockerfile` accepts both as build args — see [Docker](/configuration/docker).
