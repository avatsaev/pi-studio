PI-STUDIO · VISUAL SPEC · SESSION TREE NAVIGATION

Session tree — the map of everywhere this conversation has been

This spec is split by concern — open only the part you are building. Section numbers (§00–§15) are stable and are what the technical spec cites; every mock is real DOM at final size, styled with the app’s own custom properties. Hex appears once, in §01. Measurements in the anatomy blocks are normative; anything not stated inherits the existing component default.

Companion spec: Fork — rewind a conversation to an earlier user message. Dialog, toast and confirm patterns are inherited from it verbatim and are not re-specified here. The six open questions in the handover doc are each decided in §02, §07, §06, §04, §05, §11; where a decision could reasonably go the other way, the rejected option is named — all six are tabulated in §13 below.

13The six open questions, closed
Q
DECISION
WHY / WHAT WAS REJECTED
1
Pane tab, splittable beside the transcript (§02)
Orientation needs the transcript in view. Modal blocks it; the 232px side rail can't hold previews.
2
Flattened list, edge bar + breadcrumb (§11)
Horizontal pan loses both the preview and the structure. Depth moves into the breadcrumb.
3
Folding ships in v1, abandoned branches folded by default (§06)
Filters don't remove abandoned prompts, which is the actual noise. Cost is low; no chevron column.
4
Scroll to leaf on open + "Jump to current" pill (§06)
Minimap rejected: a column and a hit model for a question nobody asked.
5
Branch summaries read as quiet milestones (§05C)
Accent disc and chip, no bubble. Machinery contrast buries user-made content; message weight drowns a much-jumped session.
6
Silent convergence, 180ms fade on truncation (§10)
Applies to fork too. A toast either explains the user's own action or arrives stale.
14Build order
1 · The row
Guide columns, elbow, disc, preview, meta, chips, action box. Every state in §04 before any tree logic. This is the whole visual risk.
2 · The pane
Tab, header, filters, scroll, skeleton, empty, fetch failure. Land the linear case (§05A) first — it is most users' entire experience.
3 · Structure
Branching, folding, detached group, orientation pill, keyboard model. Test against a 300-node fixture, not a 12-node one.
4 · Fork handoff
Ships Phase 1. One action, one existing dialog.
5 · Jump
Behind the capability flag: dialog copy variants, summary radios, in-flight, every failure in §10. Write the failure states first — they are most of the work.
