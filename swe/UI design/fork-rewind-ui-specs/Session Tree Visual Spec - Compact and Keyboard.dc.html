Decision: flatten, don't pan. Horizontal scrolling a tree on a phone is the worst of both — you lose the preview text and the structure. Indentation collapses to two signals: a 2px left edge bar that is lit on the active path, and a 10px stub before off-path rows. Depth beyond one level is carried by the breadcrumb, not by columns.
Breadcrumb strip under the filter shows the path to the row nearest the top of the viewport, so scroll position always answers "where in the tree am I looking". It scrolls horizontally on its own, truncating from the left.
Filter becomes a Select. Fold rows stay, unchanged.
Row height rises to 44px minimum and the hover-reveal ⑂ becomes always-visible, since there is no hover. Long-press is not used.
The tree opens as a full-width pane tab below 500px; splitting is not offered.

First / last visible row
Esc
Close the dialog, then the pane tab. Blocked in flight
SEMANTICS
role="tree" on the list, role="treeitem" on rows, aria-expanded on foldable parents, aria-level from the true depth even when columns are capped.
aria-current="location" on the leaf, on exactly one row.
Roving tabindex — the tree is a single tab stop and returns focus to the last-focused row.
Accessible name per row: kind, then preview, then "on the current path" / "abandoned branch", then the label, then the timestamp. The tint and the guide weight are decorative and must not be the only carrier — §04 lists the three redundant signals.
The detached group is a nested group with an accessible name of "detached entries, not reachable from the root".
Focus on dialog close returns to the row that opened it; after a successful jump it goes to the composer for user-message jumps and to the transcript end for all others.
