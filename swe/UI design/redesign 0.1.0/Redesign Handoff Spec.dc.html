What changes. The icon rail is removed. Workspaces and their sessions live in one scrolling pane, so a workspace's full name is always legible and its sessions stay individually addressable.
  1. Workspace header = full-bleed band. surface2, 1px border top and bottom, edge-to-edge (no side margin, no radius, no card frame). Same band whether expanded or collapsed — expansion is expressed only by the chevron rotation and the presence of session rows.
  2. Header contents, in order: chevron in a 16px surface3 tile (rotate 90° when open) · 20px Avatar · name (font-weight-bold, ellipsis, never wraps) · optional StatusDot when collapsed and a child needs attention · session-count pill (surface3, radius-full).
  3. Session rows are frameless. No border, no card. Two lines: title row (ellipsis + trailing status affordance) and a meta line at font-size-3xs. Idle fill is color-mix(in srgb, var(--pi-color-surface0) 60%, transparent); hover goes to solid surface0 (equivalently the standard hover-lift mix). Padding is even (spacing-7 / spacing-10) — no left indent.
  4. Selection is unmistakable: color-mix(accent 34%, transparent) fill, 1px inset ring in color-mix(accentBright 32%, transparent), white bold title, and a 2px full-height accentBright bar on the left edge.
  5. Running ≠ selected. A running-but-unselected session keeps the normal fill and gets the spinner plus a half-opacity left bar. Selection is fill; activity is the spinner.
  6. No timestamps, no cost in the sidebar. The meta line carries status only (plus a short failure reason).

What changes. Tabs become soft pills on the pane's own header row instead of full-height bordered segments, and the tab strip becomes the pane's single piece of chrome: identity, add-tab, split controls, and turn progress all live in that 36px band.
  1. Strip geometry. Height WORKSPACE_SECONDARY_HEADER_HEIGHT (36), spacing-8 side padding, 1px bottom border, transparent background — the strip does not get its own surface step; the pane's surface0 shows through.
  2. Tab = 26px pill. radius-md, spacing-10 horizontal padding, gap: spacing-7 between icon, label, and close. Active: surface2 fill + foreground text. Inactive: no fill, foregroundMuted text, hover-lift on hover. No borders, no bottom underline on tabs — the underline treatment belongs to the Files/Changes panel tabs only, so the two never read as the same control.
  3. Truncation is mandatory. Each tab is flex: 0 1 auto; min-width: 0 with white-space: nowrap on the pill and overflow: hidden; text-overflow: ellipsis on the label span only — icon, status dot, and × stay flex: none. A long file name must shrink its own pill, never wrap it to two lines or push ＋ and the split buttons off the strip. (This was the single worst defect of the current strip.)
  4. Leading glyph states the pane kind at icon-size-xs via Icon: chat (MessageSquare, accentBright when that session is the active one), file (File, name in font-mono at font-size-2xs), terminal (SquareTerminal), viewer (Box). An unread/attention tab shows a StatusDot before the × instead of a badge.
  5. Trailing chrome, in this order: ＋ (opens the existing new-tab Menu), then margin-left:auto, then split-vertical and split-horizontal IconButtons (size="xs", hoverBase = the pane's ambient surface). All three are flex:none.
  6. Close affordance. × is always rendered on the active tab; on inactive tabs it follows hoverVisible (always shown on compact/touch). Its box is reserved either way so the label width doesn't jump on hover.
  7. The turn-progress bar hangs off the strip's bottom edge (section 05) — 2px, full pane width, immediately under the border, so a running pane is identifiable from the strip alone.

08Implementation order & guardrails
SUGGESTED SEQUENCE
1
SessionList / Sidebar — combined tree, band headers, frameless rows, states. Largest visual win, no protocol work.
2
ToolCard + Timeline rows — badge/status/output structure; delete any plan or batched-actions rendering.
3
Composer + ModelMenu move; strip the model chip from StatusBar.
4
Queue chips + TurnProgressBar — both read state that applyAgentStreamEvent already maintains.
5
FileExplorer chrome — tabs, action row, row styling, lucide icons.
6
TabStrip (section 07) — pill tabs, truncation, trailing chrome; verify each pane body scrolls independently.
VERIFY BEFORE SHIPPING
· theme/token-integrity.test.ts and font-scale.test.ts pass — no new dangling or illegal token.
· All six theme variants: check light (the mixes must darken, not lighten) and zinc (near-white accent → active session text must use accentForeground, not hardcoded white).
· Compact form factor (< 576px): sidebar band headers and chip row still fit; hover-only affordances are always visible per hoverVisible.
· Long strings: 60-char workspace name, deep file path, long model id — all ellipsis, no wrap, no layout shift.
DO NOT
· Don't copy a hex from this page into a CSS module. Use the mapped token.
· Don't use success for the green signals — it aliases the accent on dark themes. Use statusSuccess.
· Don't split a badge's background/border/text across different token families; one token, three color-mix ratios.
· Don't invent timeline rows. No plan/checklist, no batched action log, no per-session cost or timestamp in the sidebar.
· Don't add a 3 radius key or a fractional spacing key — radius-sm is close enough and dotted keys emit invalid custom properties.
· Don't render Unicode box-drawing or emoji glyphs as icons; use Icon + lucide.
· Don't hand-roll a spinner, dot, badge, dialog, or menu — Spinner, StatusDot, StatusBadge, Dialog, Menu* already exist.
· Don't put pane layout state in CSS; ResizeHandle reports deltas only.
