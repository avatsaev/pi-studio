# Task 002 — Daemon transfer hardening: paced download, clean error, owned upload streams

- **Sprint:** sprint-096-desktop-protocol-followups

- **Priority:** P1

## Goal
Make the daemon's side of file transfer bounded in memory and correct on failure.

## Context / why
Three defects found while scoping. A download reads the file as fast as the disk allows and queues every chunk on the socket, so a slow client makes the daemon buffer the whole file. A read error sends `Error` and then still sends `End` with `ok: true`. An upload frame is accepted from any session, not only the one that opened the stream.

## What to build
- `Session` exposes the socket's buffered amount when the underlying socket has one.
- Download: pause the read stream while the buffered amount is above a high-water mark and resume below a low-water mark. A session without a buffered amount is not paced.
- Download error: send `Error` and stop. No `End` follows.
- Upload: record the requesting session on the pending upload; ignore binary frames for that stream from any other session. Free the stream when its session closes.
- Tests: a slow sink keeps the number of unsent chunks bounded; a read error yields exactly one `Error` frame and no `End`; a frame from a foreign session is ignored; closing the session mid-upload closes the file handle and frees the stream.
