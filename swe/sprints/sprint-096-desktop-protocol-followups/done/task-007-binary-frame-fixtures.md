## Goal
Pin the byte layout of file-transfer and terminal frames for clients that do not use the TypeScript codec.

## Context / why
The JSON fixtures stop at the RPC boundary; the data itself travels in binary frames with a two-byte header. A Rust client re-implements that codec and needs bytes to test against.

## Scope references
- `swe/features/desktop-client-protocol-followups.md` § 3. Fixtures (binary frames, file shape)
- `packages/protocol/src/binary-frames/{file-transfer-protocol.ts,terminal-stream-protocol.ts,slots.ts}`
- `packages/protocol/fixtures/external-clients/README.md`
- `packages/protocol/src/external-fixtures.test.ts`

## What to build
- Add `binary-manifest.json` (its own `formatVersion`, starting at 1) and one fixture per frame: file transfer `Begin`, `Chunk`, `End`, `Error`; terminal `Output`, `Input`, `Resize`, `Snapshot`, `Restore`. Each has `family`, `opcode`, `direction`, `description`, `since`, `hex` (the complete frame) and `decoded`.
- A test that, for every binary fixture, decodes `hex` with the real codec and compares with `decoded`, then encodes `decoded` and compares with `hex`. It fails on an unlisted file or a missing one.
- Document the shape and the breaking-change rule for binary fixtures in the fixtures README; add a `CHANGELOG.md` entry.
- Make sure the directory still ships in the protocol package's npm `files`.
- Keep `docs/desktop-client-handoff.md` current: update whatever this task makes stale there (status table, workbench and host sections, wire facts, milestones, open questions). Say in the summary what changed in it, or that nothing did. **In a parallel wave** (av-swe `implement`), do not edit this file or `swe/features/desktop-client-protocol-followups.md` yourself — every task touches them, so they would collide: put the exact changes in your summary and the orchestrator applies them after the wave gate.
