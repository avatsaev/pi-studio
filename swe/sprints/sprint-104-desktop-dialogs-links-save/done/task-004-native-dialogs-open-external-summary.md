## What was implemented

**Shell crate (pure, tested)**
- `links::check(url) -> Result<(), Refusal>` accepts a URL of at most 8,192 characters whose scheme is `http`, `https` or `mailto`, compared without case.
  - It refuses whitespace at either end and control characters anywhere. Internal spaces are allowed.
  - It refuses any other scheme and anything without a plain RFC 3986 scheme.
  - A `Refusal`'s text holds the scheme at most, never the rest of the URL. A scheme over 32 characters is reported as "no plain scheme". This keeps log lines free of attacker text.
- `links::open(&Services, url) -> Result<(), NotOpened>` checks first, so a refused URL never reaches the hook. An accepted one reaches it once, unchanged. A missing hook gives `Unavailable`; a hook error gives `Failed(reason)`.
- `dialogs::cap_text` returns `Cow<str>`.
  - Text up to 8,192 characters is returned unchanged, without a copy.
  - Longer text becomes the first 8,191 characters plus `…`, exactly 8,192 characters in all. The cut is on a character boundary and counting stops at the cap.
- `dialogs::confirm` and `dialogs::alert` cap the text, then call the hook. A missing hook declines the confirm and drops the alert.
- `Services` is now `Clone + Default` with `confirm`, `alert` and `open_url` hooks (`Arc<dyn Fn … + Send + Sync>`).

**App**
- `src-tauri/src/services.rs` (new) holds the native hooks. `native(app, title)` builds them from the dialog and opener plug-ins, used from Rust.
  - Dialogs are titled with the product name, attached to the main window as parent, and the window is shown, un-minimised and focused first. This covers "confirm while the window is hidden".
  - Confirm uses OK/Cancel. Closing the dialog gives `false`: rfd's GTK3 backend maps delete-event to Cancel.
  - It uses `show()` with its own channel, not `blocking_show()`. The latter panics if the app is quitting. A dialog that cannot be shown answers "no".
  - Plug-in state is fetched with `try_state`, so a missing plug-in logs and declines; it never panics.
  - One dialog is open at a time. A second request waits, as the browser's blocking dialogs did.
  - `opener_plugin()` is built with `open_js_links_on_click(false)`. Otherwise the plug-in injects a script that makes the page call `plugin:opener|open_url`, for which the page has no permission.
  - `bring_forward` moved here from `main.rs` and is generic over the runtime. The single-instance callback uses it too.
- Page commands in `commands.rs`: `dialog_confirm {message} → bool`, `dialog_alert {message} → ()`, `open_external {url} → ()`.
  - All three are `async` and run the hook on `tauri::async_runtime::spawn_blocking`. A dialog therefore blocks neither the main thread, nor an async worker, nor the session-owner thread.
  - `open_external` logs a refused or failed open (`open_external: refused a link with the scheme \`file\``) and answers nothing.
- The owner thread now receives the real `Services` (`spawn_owner(info, dir, services, inbox, delay)`). The commands read a second clone from managed state.
