## What was implemented
- **Configuration directory.**
  - `main` resolves it after `Builder::build` (a failed `setup` panics in `App::run`).
  - It is `--config-dir <DIR>` or `PISTUDIODESKTOP_CONFIG_DIR`, else `app.path().app_config_dir()`. On Linux that is `~/.config/com.avatsaev.pi-studio`.
  - If no directory can be resolved, the app exits 2 with "pass --config-dir".
  - The owner thread opens `Session::with_config_dir` there and keeps the notices.
  - No engine change was needed.
- **Page commands.** The `control` / `invoke_command` commands and the `view` event are gone.
  - `boot` is async. It returns `{ app: {title, version, platform:"desktop"}, storage, notices }`. Title is the Tauri product name; version is the Cargo workspace version.
  - `storage_set {key, value}` is a sync command and answers once the write is queued. A sync command runs on the receiving thread, in the order the page made the calls.
  - An async command could be scheduled out of order, and the older of two writes of one key could win.
  - Caps are checked on the owner thread by `Session::storage_set`. A refused write is logged with the key only, and the page is not told.
  - `boot` clears the notices it returned.
- **Shell crate.**
  - `page.rs` holds `boot`, `storage_set`, `flush` and `AppInfo`.
  - `Request` is now `Control | Boot | StorageSet | Flush`. `Request::Invoke` and `menus::invoke` are removed because nothing calls them any more.
  - `owner.rs` holds `FlushTimer` and `serve`. `FlushTimer` is pure: the first unwritten change starts a 1 s countdown, later changes ride along, and a failed write retries one delay later.
  - `serve` is the owner loop. It answers requests in order, flushes when the timer is due, and flushes once more when every sender is gone.
- **Exit flush.** `bridge::on_run_event` handles `RunEvent::Exit` and sends `Request::Flush`, waiting at most 5 s. The app's own exit path leaves the files written. A signal kill does not (see Follow-ups).
- **Command list.**
  - `build.rs` calls `tauri_build::try_build` with `AppManifest::new().commands(&["boot","storage_set"])`.
  - `capabilities/default.json` grants exactly `allow-boot` and `allow-storage-set`.
  - **`core:default` is removed entirely.** The page uses no core API, and `boot` and `storage_set` work in the real webview without it.

## Follow-ups
- **Signal kills do not flush.** SIGTERM, SIGKILL and crashes skip `RunEvent::Exit`, so up to 1 s of changes can be lost. WebKitWebDriver's "close window" kills the app this way, so task-004's close-within-250 ms check must close with a WM close (my `wmclose.py` approach), not the driver. Fixing it would need a signal-hook dependency routing SIGTERM to `app.exit(0)`. I did not add one.
- **Sprint-105 preview origin.** Tauri's `is_local_url` treats any custom scheme registered with `register_uri_scheme_protocol` as local, so the preview origin may count as local for ACL purposes. The spike must verify the preview frame cannot call `ipc://`.
- **Retry on write failure.** A failed flush retries every second and logs each time. That is fine for now.
- **`permissions/autogenerated/`** is not cleaned of stale files when a command leaves the list; the stale files are harmless.
- **Next tasks:** task-002 and task-003 can use `Bridge::post`, `ask` and `AppInfo`. Adding a page command means editing three places: `build.rs`, the capability file and `generate_handler!`.
