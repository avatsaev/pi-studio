## What was implemented
- Host-key dialog (S6): after a connect fails with `host_key_unknown`, one native confirm (host, port, key type, SHA-256 fingerprint, "Role: jump host" for a hop) outside the connect. OK appends to the app's `known_hosts` and calls the trust hook (`resume::emit(Reason::Network)` in `main`, so the page gets `connection_resume`); Cancel, or a dialog that cannot be shown, is remembered per host, port and fingerprint (at most 64; `boot` and `SshSessions::close` forget them; an answer to a page that is gone is not remembered). A changed key gets no question. A failed store shows an alert and does not resume. `ConfirmHook` has only native OK/Cancel, so the text says "OK adds the key... Cancel refuses it".
- `ssh_config_hosts` page command (build.rs, capabilities `allow-ssh-config-hosts`, `generate_handler!`, test handler, capability-list test): `{hosts:[{alias, hostName?, user?, port?, identityFile?, jump?}]}`, empty for an absent file, `ssh_config` for a malformed one.
- `ui.inspect`: `connection.transports[i].via` is `direct`/`relay`/`ssh` (a link with a host hint is `direct`), `connection.ssh` is `{state: none|connecting|open, hops, channels}`; no address, user, fingerprint or link.
- `crates/ssh`: `known_hosts::describe` and `KeyDescription` (type and fingerprint) so the app needs no direct `russh` dependency.
- Docs touched: `control-protocol.md` (`ui.inspect`), `architecture.md` (`ssh_config_hosts` row), `AGENTS.md` (app description), `platform-checks.md` and `development.md` (the "`via` not yet" notes).
