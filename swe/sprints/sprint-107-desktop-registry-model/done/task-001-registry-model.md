## Goal
The daemon registry exists as plain, validated Rust types: the file's document, the three kinds of entry, every rule of the spec as a pure operation, the secret-free view, and the local daemon's state.

## Context / why
D8, D12, D24. The engine commands, the native menu, the boot snapshot and the control socket all work on the same registry and must all refuse the same things. Putting the rules in the pure bottom crate makes them testable without files or processes.

## What to build
- **Document:** `{ version: 1, lastUsedId, entries }` with entries of kind `local` (`id` "local", `name`, `password?`), `direct` (`id` UUID, `name`, `address`, `password?`), `relay` (`id` UUID, `name`, `pairingLink`). Unknown fields at both levels are kept and written back. Codec with the same three failures as the settings codec (`NotJson`, `WrongShape`, `UnknownVersion`).
- **Normalising after a read:** the `local` entry is created when missing (name "This machine"), a second `local` entry or a duplicate id makes the document `WrongShape`, and a `lastUsedId` that names no entry becomes null.
- **Operations**, each returning the changed document or one error code:
  | Operation | Refuses with |
  |---|---|
  | add direct / add relay | `invalid_name`, `name_taken`, `invalid_address`, `invalid_link`, `too_many` |
  | update (name, address, password set or cleared, pairing link) | the same, plus `not_found`, `wrong_kind` |
  | remove | `not_found`, `local_not_removable`. Removing the entry `lastUsedId` names sets it to null |
  | set last used | `not_found` |
- **Rules:** name 1–64 characters after trimming, unique without regard to case (an entry may keep its own name on update); address 1–2,048 characters; password at most 1,024 characters, empty is refused (clearing is explicit); pairing link 1–4,096 characters; at most 64 entries. The model checks sizes only: the address and the link are parsed by the workbench before they are sent.
- **`EntryView`:** `{ id, kind, name, address?, hasPassword }`. No type that holds a secret can be turned into a log line: its debug output shows a placeholder.
- **`LocalState`:** `unsupported`, `cli_missing { path? }`, `cli_outdated { version }`, `checking`, `stopped`, `starting`, `stopping`, `running { host, port }`, `failed { reason }` with `reason` one of `not_healthy`, `timeout`, `bad_output`, `spawn_failed`. JSON form: `{ state, ... }`.

## Out of scope
- Files (task-002, task-003), commands (task-003, task-004), the CLI and processes (sprint-108).

## Acceptance criteria
- [ ] A document without a `local` entry gains one; a document with two is `WrongShape`.
- [ ] Adding "Work" when "work" exists is `name_taken`; renaming "work" to "Work" on the same entry is accepted.
- [ ] A blank name, a 65-character name, a 2,049-character address, a 4,097-character link and a 65th entry are each refused with the code of the table.
- [ ] Updating a `relay` entry's address, or a `direct` entry's pairing link, is `wrong_kind`.
- [ ] Removing `local` is `local_not_removable`; removing the last-used entry leaves `lastUsedId` null.
- [ ] `EntryView` of an entry with a password has `hasPassword: true` and no other trace of it; formatting an entry for debugging prints no password and no pairing link.
- [ ] Unknown fields survive decode then encode, at document and entry level.
- [ ] Each `LocalState` value round-trips through JSON.
